# PLATING · 플레팅

HTML / CSS / Vanilla JavaScript로 만든 구독 서비스 과제입니다. 빌드·패키지 설치가 필요 없습니다.

## 과제 요구사항과 구현 위치

| 과제 조건 | 구현 |
| --- | --- |
| HTML·CSS·JavaScript 사용 | 프레임워크 없는 HTML·CSS·Vanilla JavaScript |
| 첫 번째 페이지: localStorage CRUD | `index.html`의 구독 신청(Create), 내역 조회(Read), 구독 수정(Update), 취소·삭제(Delete). `subscription.js`에서 `plating.subscriptions.v1`에 저장 |
| 두 번째 페이지: API 데이터를 UI에 표시 | `detail.html`에서 `api.js`가 USDA FoodData Central에 실제 fetch 요청 후 받은 JSON 영양정보를 카드에 표시 |
| HTML 페이지 2개 | 배포 HTML은 `index.html`, `detail.html` 두 개. 첫 HTML의 메뉴·구독·내역은 URL별 내부 화면 |

제출 시 두 HTML과 CSS·JS·assets를 함께 제출하세요. 상품을 클릭하면 두 번째 페이지로 이동합니다. 카카오 주소 검증은 첫 페이지의 추가 API 기능이며 두 번째 페이지의 USDA API와 별개입니다.

## 실행 및 화면 이동

공개 웹사이트: https://hyeok-747-del.github.io/19_plating/

GitHub Pages에서 카카오 지도를 사용하려면 해당 JavaScript 키의 SDK 도메인에 **`https://hyeok-747-del.github.io`**를 추가하세요. `/19_plating/` 경로는 등록값에서 제외합니다. 기존 Live Server 도메인은 함께 유지할 수 있습니다.

VS Code에서 `plating` 폴더를 열고 `index.html`을 우클릭 → **Open with Live Server**를 선택하세요.

HTML 파일 2개를 유지하면서 URL별로 화면을 분리했습니다. 한 화면에는 해당 페이지 콘텐츠만 표시됩니다.

- `index.html`: 홈, 브랜드 소개, 사진이 있는 자동 후기 슬라이드
- `index.html?page=menu`: 이번 달의 메뉴 캘린더와 전체 상품
- `index.html?page=subscribe`: 요일·기간 선택 및 주문 요약
- `index.html?page=history`: 구독 조회·수정·삭제
- `detail.html?id=green`: 상품 상세와 USDA 영양정보 검색

메뉴 클릭, 새로고침, 직접 링크, 브라우저 뒤로가기를 지원합니다. 화면 이동 중에는 작성 중인 폼을 유지합니다. 새로고침하면 신청 전 입력은 초기화됩니다. 이미 저장된 구독은 유지됩니다.

## 파일과 편집 위치

- `products.js`: 샐러드 12종, 주스·음료 8종, 샌드위치·도시락의 상품명·가격·사진·재료·알레르기·샘플 영양정보. `MENU_CYCLE`에서 4주·12회 순환 조합을 수정합니다. `menuForDate()`가 날짜별 기본 두 메뉴를 결정합니다. 새 상품을 기본 식단에 넣으려면 `MENU_CYCLE`에 해당 상품 ID를 추가하세요.
- `subscription.js`: 출고 일정·주문 요약·알레르기 경고·localStorage CRUD.
- `views.js`: URL 화면 이동, 월간 캘린더, 가상 후기와 슬라이드 제어.
- `api.js`: 상품 상세와 USDA 실제 fetch 요청, 영양소 매핑.
- `delivery-config.js`: 카카오 JavaScript 키, 배송 가능 구, 배송 제외 행정동 배열.
- `delivery.js`: 카카오 주소 검색·좌표→행정동 검증·지도·마커·신청 가능 상태.
- `style.css`: 공통 디자인·반응형·자동 슬라이드.
- `assets/`: Unsplash에서 받은 로컬 사진. 여러 샘플 상품이 연출 사진을 공유합니다. 상품 이미지는 직접 교체할 수 있습니다.

사진은 로컬 파일이므로 인터넷 없이 표시됩니다. Google Fonts는 연결되지 않으면 시스템 글꼴로 대체됩니다. 외부 영양정보 검색에는 인터넷이 필요합니다.

## 월간 식단과 주문

캘린더는 현재 달로 시작하며 이전 달·다음 달·이번 달 이동을 지원합니다. 작은 화면에서는 달력 영역만 좌우로 스크롤합니다. **월·수·금에만 2가지 메뉴를 편성하고 배송합니다.** 화·목·토·일에는 메뉴 없이 ‘배송 없음’을 표시합니다.

`menuForDate()`는 같은 날짜에 같은 메뉴를 반환하므로 캘린더와 구독 일정이 일치합니다. 편성 함수나 상품 목록을 바꾸면 향후 생성되는 식단이 달라집니다. 이미 저장한 구독의 메뉴와 금액은 저장 당시 값을 유지하고, 수정 저장할 때 새 편성을 반영합니다.

주 1·2·3회 중 선택한 횟수만큼 출고 요일을 고릅니다. 기간은 1·2·3·4주입니다. 출고 1회당 샐러드 2팩이며, 첫 선택 요일부터 7일 단위로 계산합니다. 주 2회 × 4주는 **8회 / 16팩**, 주 3회 × 4주는 **12회 / 24팩**입니다. 금액은 출고 날짜별 메뉴 가격을 합산합니다.

알레르기 선택 영역을 강조하고, 해당 성분이 포함된 메뉴는 빨간 경고 배경과 목록으로 안내합니다. **알레르기를 이유로 구매를 제한하지 않으며 메뉴를 자동 교체하지 않습니다.** 배송지 검증은 별도 필수 조건입니다. 4주의 인기 표시와 홈 이용후기는 과제용 예시입니다. 실제 주문 통계나 고객 후기로 표현하지 않습니다. 후기 이름은 `박*혁`처럼 가운데를 가립니다.

### 기본 그대로 또는 대체 샐러드 두 팩

구독의 **나의 출고 일정 · 메뉴 변경**에서 날짜마다 선택합니다.

- **기본 식단 그대로**: 알레르기 경고가 있어도 기본 메뉴로 주문할 수 있습니다.
- **대체 샐러드 2팩 선택**: 두 선택창에서 각각 메뉴를 고릅니다. 체크한 성분이 없는 등록 샐러드를 대체 후보로 제공합니다. 두 창에서 동일 상품을 선택하거나 **첫 번째와 같은 상품으로 2팩 받기**를 누를 수 있습니다.
- 메뉴 가격에 따라 금액이 즉시 재계산되며 팩 수는 항상 출고당 2팩입니다. 선택 내용은 저장·새로고침·수정 시 유지합니다. ‘기본 식단 그대로’를 다시 선택하면 해당 날짜의 기본 조합으로 돌아갑니다.
- 대체 선택 후 알레르기 체크를 바꾸면 이미 선택한 메뉴를 임의로 지우지 않고, 새로 충돌하는 성분을 다시 경고합니다. 현재 선택에 포함된 메뉴와 대체 후보를 함께 확인할 수 있습니다.

기본 식단은 단백질 중심 메뉴와 채소·곡물 메뉴를 조합한 4주 순환 샘플입니다. 대체 상품 두 팩이 동일해도 주문할 수 있지만, 전문적인 개인별 영양 처방은 아닙니다. 알레르기 안내는 등록 재료 기준이며 제조 환경의 교차 접촉까지 보장하지 않습니다.

## 카카오맵 배송 가능 지역 설정

1. [카카오 Developers](https://developers.kakao.com/)에서 앱을 생성하고 카카오맵 사용 설정을 활성화합니다.
2. [공식 웹 설정 안내](https://apis.map.kakao.com/web/guide/)에 따라 웹 플랫폼/JavaScript 키의 허용 도메인에 실제 Live Server 출처를 등록합니다. 예: `http://127.0.0.1:5500`, `http://localhost:5500`. 실행 주소와 포트가 일치해야 합니다.
3. **JavaScript 키**를 `delivery-config.js`의 `kakaoJavascriptKey`에 입력하거나, 배송지 영역의 **카카오 API 설정 및 배송지역 테스트**를 펼쳐 입력합니다. REST API 키가 아닙니다. 화면에서 입력한 키는 현재 탭 메모리에만 보관하고 localStorage에 저장하지 않습니다. JavaScript 키는 브라우저에 노출되는 공개 클라이언트 키이므로 허용 도메인을 제한하세요.
4. 도로명+건물번호 또는 지번 주소를 검색합니다. 설정이 끝나면 입력 후 자동 검색하거나 ‘배송지 확인’을 클릭할 수 있습니다. 상세 동·호수는 별도 상세 주소에 입력합니다.

**‘카카오 지도 설정이 필요합니다’ 오류를 해결하는 정확한 순서**

이 오류는 `delivery-config.js`의 `kakaoJavascriptKey: ''`가 비어 있고 화면 입력란에도 키가 없어서 발생합니다.

1. 카카오 Developers → 내 애플리케이션에서 앱을 생성합니다.
2. 공식 가이드 기준 **앱 → 앱 설정 → 앱 → 플랫폼 키**에서 **JavaScript 키**를 확인합니다.
3. 해당 키의 **JavaScript SDK 도메인**에 실제 Live Server 출처를 등록합니다. 주소가 `http://127.0.0.1:5500/index.html`이면 등록값은 **`http://127.0.0.1:5500`**입니다. `/index.html`이나 `?page=subscribe`는 넣지 않습니다. `localhost`로 접속하면 `http://localhost:5500`도 별도로 등록합니다. 포트가 다르면 실제 포트를 등록하세요.
4. 화면에서 ‘카카오 API 설정 및 배송지역 테스트’ → JavaScript 키에 붙여 넣거나, `delivery-config.js`에서 `kakaoJavascriptKey: '발급받은_JavaScript_키'`로 설정합니다.
5. Live Server에서 새로고침하고 배송 주소를 다시 검색합니다. SDK를 이미 다른 키로 불러왔으면 반드시 새로고침해야 합니다.
6. 키를 넣었는데도 실패하면 앱의 카카오맵 사용 가능 상태, 키 종류, 허용 도메인과 현재 접속 주소, 네트워크·광고 차단 확장을 확인합니다.

**실제 SDK 진단에서 401 `domain mismatched`가 나오면** 키 발급은 되어 있지만 접속 도메인이 해당 JavaScript 키에 등록되지 않은 상태입니다. 플랫폼 키 화면의 **Default JS Key를 클릭**하고 JavaScript SDK 도메인에 실제 접속 출처를 추가하세요. 예를 들어 `http://127.0.0.1:5500`과 `http://localhost:5500`은 서로 다른 도메인 설정입니다. 브라우저 주소가 5501 포트면 5501을 등록해야 합니다. 설정 후 저장하고 `Ctrl+Shift+R`로 새로고침하세요.

구독 화면에 진입하면 키가 설정된 경우 대구 중심 지도를 먼저 불러옵니다. 지도 로드가 실패하면 지도 영역에 설정 방법과 재시도 버튼을 표시합니다. 주소 검색 후에만 해당 위치에 마커를 표시하고 배송 가능 여부를 판정합니다.

키 미설정 오류 시 설정 안내를 자동으로 펼치고, 등록할 현재 SDK 도메인을 표시합니다. 카카오는 USDA의 DEMO_KEY와 같은 공용 체험 키를 여기서 제공하지 않으므로, 사용자 앱의 키 발급이 필요합니다. 유효한 키 없이 주소를 배송 가능으로 간주하지 않습니다.

SDK를 `https://dapi.kakao.com/v2/maps/sdk.js?...&libraries=services&autoload=false`로 실제 로드하며, `Geocoder.addressSearch()`와 `coord2RegionCode()`를 순서대로 호출합니다. 지도에 좌표와 마커를 표시하고 API 응답의 행정동 코드도 화면에서 확인할 수 있습니다.

대구 **동구·중구 전체**, **수성구(파동 제외)**, **북구(아래 제외 동 제외)**만 허용합니다. 제외 목록은 `excludedAdministrativeDongs` 배열에서 수정합니다.

- 수성구: 파동
- 북구: 관문동, 태전1동, 태전2동, 구암동, 읍내동, 동천동, 국우동

입력 주소 문자열의 단어 포함 여부를 사용하지 않습니다. 좌표 API의 `region_type: H` 응답에 있는 행정동 이름과 시·구를 정확하게 비교하고, 해당 행정동 `code`가 주소 검색의 `address.h_code`와 같은지 대조합니다. 법정동(B) 코드도 `address.b_code`와 대조합니다. 코드·좌표·행정구역이 누락되거나 서로 다르면 배송 가능으로 처리하지 않습니다. 다중 검색 결과는 고객이 정확한 주소를 선택해야 하며, 검색 범위가 너무 넓으면 재검색을 안내합니다.

**실제 카카오 API로 동구청·중구청·파동·태전2동 주소의 응답과 행정동 코드를 확인했습니다.** 추측한 코드를 제품 설정에 넣지 않았습니다. `excludedAdministrativeCodes`는 비워 두었으며, 실제 응답을 확인한 코드를 추가할 때만 사용합니다. 기본 제외 판정은 API의 구조화된 행정동 이름과 반환 코드의 교차 검증으로 작동합니다. 주소 API의 ‘대구’와 좌표 API의 ‘대구광역시’는 같은 시로 정규화하여 비교합니다. 행정동·법정동 코드 비교는 계속 정확히 일치해야 합니다. 자동검사는 가짜 SDK·합성 코드에 더해 실제 API에서 받은 공공기관 응답 자료를 tests/kakao-public-addresses.json에 기록하여 회귀검사합니다. 자동검사 자체가 매번 실시간 API를 호출하는 것은 아닙니다.

미검증·검증 중·제외지역·API 오류 상태에서는 버튼과 submit 처리를 모두 차단합니다. 주소 입력 변경, 구독 수정 진입, 새로고침 때는 반드시 재검증합니다. 오래된 비동기 응답은 무시합니다. 구독을 저장할 때 검증 주소·좌표·행정동 코드·검증 시각을 내역에 함께 보관하지만, 이 과거 기록으로 새 신청을 승인하지 않습니다.

## USDA FoodData Central API

영양정보는 기존 API를 제거하고 USDA만 사용합니다.

- 공식 안내: https://fdc.nal.usda.gov/api-guide/
- 키 신청: https://fdc.nal.usda.gov/api-key-signup/
- 요청: `https://api.nal.usda.gov/fdc/v1/foods/search?api_key=DEMO_KEY&query=vegetable%20salad&pageSize=5&dataType=SR%20Legacy`

상세페이지 진입 시 `fetch()`와 `async/await`로 실제 JSON 요청을 보냅니다. 키가 없으면 공식 **DEMO_KEY**를 사용합니다. 체험 키는 IP당 시간당 30회, 일일 50회로 제한됩니다. 위 발급 페이지에서 신청한 개인 키를 상세 화면의 **USDA API 인증키**에 입력하면 해당 키로 조회합니다. 키는 브라우저 저장소에 저장하지 않습니다. `API_CONFIG.key`에 개발용 기본키를 넣을 수도 있지만 공개 코드에 키를 저장하지 마세요. 정적 클라이언트의 요청 URL에서 키를 숨길 수 없습니다.

샐러드·오렌지주스·사과주스·샌드위치·도시락은 영문 검색어로 변환합니다. 다른 식품은 영문명으로 검색하세요. API 원문 식품명은 번역하지 않고 원문임을 표시합니다. 나머지 안내와 영양소 이름은 한국어입니다.

`foods[].foodNutrients`에서 영양소 ID로 열량·탄수화물·단백질·지방·당류·나트륨을 읽습니다. **SR Legacy 자료의 100g 기준**이며 판매 상품 1팩 전체의 샘플값과 별도로 표시합니다. 누락값은 미제공, 실제 0값은 0으로 표시합니다. 로딩, 빈 결과, HTTP 오류, 429 호출 한도, 네트워크 오류, 잘못된 JSON, 15초 시간 초과를 처리합니다. API가 실패해도 상세페이지는 정상 표시됩니다. 가짜 성공 응답은 제품 코드에 없습니다.

## 확인 순서

1. 홈에서 메뉴 클릭 → 다른 홈 콘텐츠가 사라지고 메뉴 화면이 표시되는지 확인합니다. 새로고침·뒤로가기·직접 링크도 확인합니다.
2. 월간 캘린더의 이전·다음 달과 2월 윤년 날짜를 확인합니다. 월·수·금의 메뉴를 메모하고 같은 날짜의 구독 일정과 비교합니다.
3. 구독에서 주당 횟수·기간·요일을 바꾸고 요약의 요일·출고 횟수·팩 수·금액을 확인합니다.
4. 알레르기를 체크해 빨간 해당 메뉴 경고를 확인합니다. 요일 수가 올바르고 배송 가능 주소로 검증되면 경고가 있어도 신청할 수 있어야 합니다.
5. 테스트 이름·연락처·배송 가능 지역의 주소를 입력하고 카카오로 주소를 검증한 후 저장 동의·신청합니다. 내역 화면으로 이동하고 새로고침 후에도 내역이 남는지 확인합니다.
6. 구독 수정 → 배송지 재검증 → 기간·요일·주소 변경 → 저장. 주소를 다시 변경하면 다시 검증해야 합니다. 내역 수가 늘지 않고 변경되는지 확인합니다. 수정 취소와 삭제 확인 창도 확인합니다.
7. 후기 슬라이드는 계속 재생되며 정지 버튼과 마우스·키보드 접근 정지 기능은 없습니다. 운영체제의 모션 줄이기가 켜져 있으면 자동 재생 대신 가로 스크롤을 제공합니다.
8. 상세페이지에서 USDA 조회와 로딩·오류·빈 결과를 확인합니다. 인증키 없이도 체험 키의 잔여 한도 안에서 실제 조회합니다.

이름·연락처와 구독 내역은 `plating.subscriptions.v1` localStorage에만 저장하며 구독 서버로 전송하지 않습니다. **주소 검색 시에는 입력 주소와 좌표를 카카오에 전송합니다.** 브라우저·호스트·포트가 바뀌면 저장소가 다릅니다. 저장 차단 시 오류를 안내합니다. 공용 기기에서는 이용 후 내역을 삭제하세요.
